The current combined source template filters `P.manifest.challenge` by concept prefix and source, then passes a fixed array to `NovaLessonChallenge`. Its `buildMission`, `paint` and New game closures use that array. There is no bank consumer or New game sampler yet. Implement the following narrow extension in the local shared controller and its embedded derived-template counterpart, not a parallel game.

1. Read `P.questionBanks` (proposed integration key; you must add and document its consumer) and map each bank to the actual concept ID, source alias and 6–8 round setting. Use full native records whose `id` retains the `C1.`/`C2.` prefix expected by the real host. The 38 bank IDs remain stable even when displayed as HUD Question 1 of 8. Do not rename them to make bank coverage ambiguous.
2. At first session creation, sample exactly once via `NovaChallengeSampler.select(bank,{rounds,seed,recentSelections})`. Keep seed, selected bank IDs, selected records, round setting, history and current progress together in the existing concept session. The helper returns JSON-safe records; do not mutate the bank while painting a round.
3. Build original tasks, paint and marking from that same selected-record array. A wrong response, hint, redraw, resize, navigation, mode return or reload must use the stored session. Restoring a session restores the order/values/score/index consistently; do not restore a score against a fresh random list. If a source's current controller does not persist challenge sessions across reload, implement an isolated lesson+concept storage hook or explicitly document the supported restoration scope; do not claim unimplemented persistence.
