Native Bob portrait/mascots as supplied.

## Fixed seven-page shell (v37.3)
Navigation **Start, Learn, Explore, Examples** upper and **Challenge, Practice, Exit** lower. No standalone games, extra lesson pages or duplicated Learn Explore/Challenge tabs. Native Bob Board area exactly 700px desktop at 100% zoom, normal page scrolling allowed. DO NOT alter the approved Bob Board design when it is working.

**Start:** exact master objective; Bob's Big Idea, introduction, five diagnosis S1–S5. Static aid images S1,S2 only, MCQs S2,S3. Images are mathematical drawings ONLY, no controls, dropdowns, draggable slots, toolbars, helper buttons, marking hints, spoilers or answers.

**Learn:** five separate Watch presentations and one continuous Bob Board spanning five concepts with 4–6 beats each, 20–30 total. Genuine native animation with observable **before → intermediate motion → after**, especially exchange, grouping, expansion, fraction re-partition/equivalence, simplification and number shifts when supported. Written chalk steps move with visual maths. **The existing original component Play/Pause/Next controls trigger TTS as well as Watch actions. No added Play Watch or TTS buttons.** Playback skip while playing remains playing, paused skipping remains paused; cancel stale speech on skip/stop/page change. Bob keywords are individually clickable definitions; never interrupt narration.

**Explore:** a dedicated vertically scrolling workshop with full-width apparatus cards. **All five mathematical concepts must have distinct meaningful learner tasks**, but **not necessarily five copies of an apparatus**. Prefer each genuinely distinct original source once, with separate named Task A/Task B where one source supports several concepts. One full-width station may cover multiple concept tasks. Each station explains its purpose, the actual native controls the pupil can see/use (drag, buttons, scales, reset), what to look for, mathematical takeaway and accessible input route. No unrelated repeated place-value chart, tiny three-column panels, fake interactivity or control instructions that do not exist.

**Examples:** up to FIVE total original Guided examples, normally one per concept. Each includes native visual, multiple narrated *steps* (not extra examples), written work, initial/intermediate/final mathematical states, real native motion where supported. Uses the original existing Play control and same Bob voice.

**Challenge:** ONE lesson-wide original canonical F0-12 game, 10 standard (two per concept preferred) and 5 optional Stretch (one per concept preferred). **Upon first opening Challenge, Question 1 is already present and answerable. NO additional Start/Play Challenge button.** The 5 optional questions can be selected before answering the first question or via deliberate session restart; do not create a second game. Exactly one running original `F0-12.html`/`NovaGameWrapper`/`NOVA.game.create`, using its real HUD, question card, lives, streak, hint, results, points and completion. Native game is visibly rendered, not just used internally to calculate a score while an invented parent HUD is shown. Correct auto-advances; wrong retains question/state and visibly says NOT QUITE. Challenge question-specific original mathematical apparatus must be loaded with exact public numeric state and hold still until action/next question; no unrelated slideshow or answer spoilers.

**Challenge full-width template contract:** `.nova-challenge-main` and `#novaLessonGame` are the ONE NOVA dark `#071929` hosting surface. The actual F0-12 `iframe.nova-f012-native-controller` must span 100% of `#novaLessonGame` and its **internal document** must not be hard-coded to `760px`. The apparatus below it and answer/feedback controls must occupy the same continuous dark surface, with identical palette and no nested off-green/teal cards or large blank gutters. Native mathematical SVG may preserve original geometry/aspect ratio; provide full-width host fit without cropping. F0 results belong to that same controller. Preserve correct mobile scrolling and keyboard reachability. The v37.3 template supplies this host/role; populate it, do not reconstruct it.

**Practice:** 15 questions exactly: Core P1–P5, Secure P6–P10, Stretch P11–P15. Static visual aids ONLY at P1,P2,P6,P11. Keep meaningful progression and question-specific unspoiled art. Teacher-reviewed written answers are saved for review, not auto-marked as incorrect.

**Exit:** five independent questions, 2 Core (X1/2), 2 Secure (X3/4), 1 Stretch (X5), no visuals and no instant solution leak.

Learn Watch, Examples Guided, Challenge and Board must not use a different browser default voice. Existing controls handle Play/Pause/Stop/Skip and cancel/restart narration consistently. All Challenge numeric givens, source state, question text, units, diagram, operators, public options, hidden answer and feedback must agree. Randomize MCQ correct-slot locations with value-based answer keys, preserve concept coverage and QA reproducible seed. Challenge scores must count **distinct completed questions**: avoid Lesson 20 `15/30` when wrong retries occurred. Check that game star thresholds are consistent with available rounds/points. Never show verdict text such as `different lengths` or simplified fraction before learner responds. Explicit `✓ CORRECT` / `✕ NOT QUITE` on checkable responses; written long answers show `ANSWER SAVED FOR REVIEW` and parent/teacher marking; Exit follows delayed review contract.

## Proof requirements and hard blockers
Every mapped source, alias/preset and hash verified; actual first-frame and after-idle numeric state for every Challenge visual; all 6 assessment aids reviewed visually at native resolution; initial/intermediate/final animation for at least each required native transform and all examples/concepts; all 5 native Watch controls, TTS, five concept Explore task coverage, F0 10+5 complete, wrong/right, lives, reset/hints/results, desktop 1280+ and 390 mobile, keyboard navigation, native app console, real-origin autosave/hand-in tested. Never mark GOLD from static counts or headless speech API alone. Record PASS/FAIL/NOT VERIFIED per check; any mandatory failure → REVIEW.
